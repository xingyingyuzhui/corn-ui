# Corn UI 设计工作流

> 目标：每个界面都能用 Corn UI 语言做出识别性，而不是拼一堆通用卡片。

## 主流程

1. **产品事实**：写清用户是谁、这是什么产品、核心任务、真实内容（不是 lorem）、设备与约束。信息缺到会改变方向时才集中问一次；能推断的自己定并说明假设。
2. **主角/动作**：每屏只认一个主角、一个主动作。次要动作降级为 ghost 按钮或链接；装饰先删。
3. **灰度结构**：先排内容层级与布局（字号阶梯、间距、面的分合），结构走不通不进入配色。
4. **上语言**：用 token 和 `.corn-` 组件实现。颜色不许绕过 token 自造；先想"这在田里是什么"，再想"用什么变量"。
5. **真实画面验收**：在目标视口打开看实际渲染（桌面与移动各至少一档），对照 `references/review.md` 清单逐项检查，再交付。

## 交付物形态

- **组件片段**：`packages/ui/components/*.html`，可直接拷入项目。
- **页面**：引两个 CSS 文件搭建；页面专属样式写在页面 `<style>` 里，不回写进 `corn.css`（除非沉淀为通用组件）。
- **设计规范沉淀**：项目里出现与本文冲突的设计文档时，列出冲突交给用户，不擅自合并。

## 什么算"做完了"

- 只用了 tokens 里定义的颜色/字体/圆角/动效；
- 每屏有一个清楚的主角和主动作；
- maize 出现次数少而准（eyebrow、focus、至多一处主强调）；
- 桌面与移动各看过一次真实渲染，无横向溢出；
- 焦点可见（`:focus-visible` 描边），控件有 hover/active/disabled 状态。

## 范围判断

- 改文案、调数量、删指定元素 → 直接改，一两句交付说明，不走流程。
- 新界面、风格探索、存量重设计 → 走完整流程。
- 只要评审不改文件 → 按 `references/review.md` 出证据与建议后停止。
